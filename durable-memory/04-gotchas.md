# Gotchas and limits

- **The schema bytes are part of the bytecode binding.** lmscript embeds the schema hash in `.dslb`; changing even whitespace in the schema after compilation makes the host refuse the chunk. Compile and run against the same file. The compiler requires schema `name` to be an identifier (`lmcad`, not `lmcad-v0`); a host function name also cannot be reused as a DSL local variable (`material` was rejected as a local, so examples use `mat`).
- **Compiler must be new enough.** lmscript 0.2.298 predates `_dsl_`; use 0.2.328 or later. The accepted schema type spellings (`float`, `string`, `int`, `bool`), `context: {"scene":"Scene"}`, `material()` function, return types and calls in the v0 schema were exercised with 0.2.333.
- **Camera is required for render.** The host checks it at the time `render_png` / `render_ppm` runs and returns DSL runtime error 3 if absent. Output width/height must be positive, at most 8192 each, and at most 16,777,216 pixels total.
- **Scene allocation is bounded.** Each run permits at most 4096 shapes and 4096 materials, with shape names limited to 1024 bytes; exceeding a cap returns runtime error 3.
- **Finite positive dimensions and transforms.** Primitive dimensions and scale magnitudes must be finite and positive/nonzero. Color channels and roughness are in `[0,1]`; light intensity is finite and nonnegative. Rotations are radians. Camera vertical view directions parallel to world up are refused because this first camera has no configurable up vector.
- **Primitive/material semantics are intentionally small.** Meshes are faceted triangles (sphere 20 segments x 12 rings; cylinder 24 segments). The renderer uses flat Lambert shading with ambient fill; material roughness is stored but not yet used. Materials are copied onto a shape when it is created, so later edits to the material handle do not change existing shapes.
- **Raster clipping.** Triangles are clipped against all six camera frustum planes before projection; depth uses reciprocal interpolation. There is no anti-aliasing, shadow map, transparency, texture mapping or CSG.
- **PNG prioritizes self-containment.** Stored DEFLATE blocks are valid but uncompressed, so PNG output is larger than a compressed encoder would produce (the 640x480 sample is about 0.9 MB). The unit test independently checks chunk CRCs, stored-block integrity, Adler-32 and repeatability.
- **Exports are mesh-level.** STL is binary and drops material/color data. OBJ writes vertices/faces only and does not produce an MTL file. Neither export requires a camera. STL facet count is limited by its 32-bit format field.
- **Static means target-specific.** Full static linking worked on the current ARM64/glibc toolchain. A fully static glibc binary can have host OS compatibility constraints; validate each supported release target rather than assuming this artifact runs everywhere.
- **No loops yet.** v3 bytecode has forward-only jumps; animation and keyframes still need coordinated language/SDK work described in `04-loops-and-collections-notes.md`.
